# Step 12 — Licence submission and white-label branding

**Phase:** Phase 2 — Clients
**PRD refs:** ORG-02, BRAND-01
**Depends on:** 09, 10, 04
**Branch:** `stage1/12-licence-branding`

## Goal
A DPCO can submit their licence and set up the branding their packs will carry.

## Scope
**In**
- `POST /v1/orgs/{orgId}/licence` (Owner) sets status to pending
- `PUT /branding`: logo PNG or SVG up to 1 MB (SVG sanitised), firm name, primary colour, contact block, licence number
- S3 client in a shared package (SeaweedFS in dev); pre-signed 5-minute URLs
- Settings UI with a live pack-cover preview
- Audit log entries

**Out**
- Admin approval (Step 30)
- Pack rendering (Step 25)

## Files / packages touched
- apps/api/src/orgs/branding/**, packages/storage, apps/web settings

## Notes
Done 2026-11-21.
- **`packages/storage` (`@ndpa/storage`):** an `ObjectStore` over the S3 API using AWS SDK v3. R2 in production, SeaweedFS in dev and tests.
  - `put` returns the key, SHA-256 and size.
  - `presignGet` gives 5-minute URLs (PRD §7), with an optional download filename.
  - `ensureBucket` is for dev and tests only; production buckets come from Terraform.
- **API:** `S3_*` config, and a global `StorageModule` providing `ObjectStore`.
- **ORG-02:** `POST /v1/orgs/{orgId}/licence` (Owner only) normalises the number and sets the status to `pending`, which clears any earlier verification. If the licence is already verified, a new number gets 409 (contact support) and resending the same number changes nothing. Audit: `licence.submitted`.
- **BRAND-01:**
  - `GET /v1/orgs/{orgId}/branding` (any member) returns the branding plus a pre-signed `logoUrl`.
  - `PUT /branding` (Admin) saves the firm name, colour, contact block and "show licence on cover". **The colour is refused if its contrast on a white cover is below 3:1**, so a cover can't be made unreadable.
  - `PUT /branding/logo` (Admin) takes the raw PNG or SVG body, up to 1 MB (Express raw parser; too large → 413 problem+json). It checks PNG magic bytes, and **refuses SVGs containing scripts, event handlers, foreignObject, entities or DOCTYPE, javascript: links, external href/src/url(), or iframe/embed/object/use**.
  - Logos are stored content-addressed at `orgs/{orgId}/branding/logo-{sha256}.{ext}` and are only ever served through pre-signed URLs into `<img>`.
  - Audit: `branding.updated`, `branding.logo_uploaded`.
- The problem filter now maps body-parser 4xx errors (413, 415) to problem+json instead of 500.
- **Web, Organisation settings:**
  - Licence section: status in colour, licence number, submit or resubmit for Owners.
  - Pack branding section: logo upload with client-side type and size checks, firm name, colour picker, contact block, licence toggle, and a **live pack-cover preview** that matches BRAND-02 (DPCO brand first, "generated by NDPA Lens" as one small line).
  - The API client gained `put` and `RawBody` for byte uploads.
- **Tests:**
  - `@ndpa/storage`: 3 tests on a SeaweedFS Testcontainer (round-trip and hash, anonymous 403 versus pre-signed 200, idempotent bucket creation).
  - API: 85 tests (7 new). Only an Owner can submit a licence; it normalises and goes pending; Analysts get 403 on PUT while every member can read; light colours are refused; PNG is stored by hash and fetched through a 300 s URL; saving branding keeps the logo; a plain SVG is accepted; five malicious SVGs, a fake PNG and an oversized file (413) are refused; audit events are written; the tenant harness covers the new routes.
  - E2E: the founder journey now submits a licence, uploads a logo, saves branding and checks the preview text, with axe on the settings page (which caught an unlabelled file input, now fixed). 5/5 passing.
- **Not built:** hiding the "generated by NDPA Lens" line on paid plans (BRAND-02 says Owners can hide it on paid plans, so it waits for billing in Step 28). Admin verification of licences is Step 30.
